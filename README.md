# AstrBot 多模型生图插件

一个指令调用七个生图渠道，支持文生图、图生图、ComfyUI 多工作流，以及 NewAPI / OneAPI 等 OpenAI 兼容中转站。

**本文对应插件 v0.2.0，最低支持 AstrBot 4.28.0。** 已验证 AstrBot 4.28.0 与 4.29.1 的关键流程和配置保存／重载。

所有参数均在 **AstrBot 标准插件配置页**管理，包括模型选择、尺寸预设和连通性结果，无需额外的自定义页面。

| 渠道 | 接入方式 | 模型示例 |
| --- | --- | --- |
| `gpt` | 通用 OpenAI 兼容接口，也可接中转站 | `gpt-image-1`、站点提供的 FLUX 等生图模型 |
| `gemini` | Gemini 原生、Imagen、OpenAI 兼容接口 | `gemini-2.5-flash-image`、`imagen-*` |
| `comfyui` | 已部署的 ComfyUI，支持多套 API 工作流 | 自定义工作流 |
| `seedream` | 火山方舟 `/api/v3` | `doubao-seedream-4-0-250828`、`doubao-seedream-4-5-251128` |
| `grok` | xAI 或兼容中转站 | `grok-imagine-image-2.0` |
| `jimeng` | 使用 sessionid 的第三方转换服务 | `jimeng-4.0` 等服务端支持的模型 |
| `qwen` | 阿里云百炼原生接口，同步生成或异步任务 | `qwen-image-2.0`、`wan2.7-image` |

模型名称只是配置示例，实际可用范围取决于所填地址、Key、已开通模型及服务端协议。

## 快速开始

1. 在 AstrBot 管理面板的插件页安装插件 ZIP，或将插件目录放入 `data/plugins/` 后重载。
2. 打开「插件 → 多模型生图 → 配置」，配置任意一个渠道。通常需要 API 地址、Key 和模型名称；ComfyUI 使用地址与工作流模板。
3. 保存配置。支持自动模型目录的渠道会后台读取模型列表，等待读取完成后，重新打开配置页选择模型并再次保存。
4. 将「默认生图渠道」设为已经配好的渠道，或在指令中直接指定渠道。
5. 发送：

   ```text
   /draw 一只坐在窗边的橘猫，柔和自然光
   /draw seedream 中国古风庭院，细腻插画
   ```

七个渠道互相独立，**配好一个就可以使用**。没有 ComfyUI 或即梦转换服务时，将相应渠道留空即可。

运行依赖为 `httpx>=0.24`，声明在 `requirements.txt` 中。

## 模型选择与连通性测试

### 根据地址和 Key 选择模型

GPT、Gemini、Seedream、Grok、即梦支持读取已保存凭证对应的模型目录，并在「模型名称」中显示识别为生图／编辑用途的模型。

1. 填写渠道地址、Key 和调用协议，保存。
2. 等待后台读取完成，再重新打开标准配置页。
3. 从「模型名称」下拉框选择模型，保存生效。

目录读取失败、没有识别到生图模型或凭证不完整时，保留手动输入框。需要填写目录未包含的模型时，开启该渠道的「手动填写模型名称」，保存并重新打开配置即可输入。

已有模型即使未出现在目录中也会保留，不会自动替换为另一个模型。模型识别依据目录内容和模型名称特征，无法保证覆盖所有自定义命名；下拉框可见也不等于有余额或实际生图权限。

百炼使用配置内置的模型选项；ComfyUI 选择的是工作流模板。它们不属于上述动态模型目录功能。

### 在标准配置页查看连接和延迟

开启顶部的 **「保存后测试连通性」**，保存后等测试完成，再重新打开配置页查看：

- 最近测试时间；
- 各渠道的连接状态、HTTP 状态和错误原因；
- 只读请求的耗时，单位为毫秒。

此开关默认关闭。开启后，保存配置触发的重载、手动重载和启动也会执行检测，最多同时检查 3 个渠道，单渠道总时间上限为 15 秒。

检测只发送 GET 请求，不提交生图任务，也不执行 ComfyUI 工作流。**显示的延迟是只读接口耗时，不是图片生成耗时。** 对缺少可靠只读鉴权接口的服务，可能显示「待确认」；这不能直接判定为生图失败。

关闭此开关会停止记录连通性测试结果，但开启动态模型选择的渠道仍会读取模型目录。模型目录读取同样不生成图片。

## 尺寸与常用参数预设

每个渠道分别设置「常用参数预设」，无需配置全局默认宽高。

| 选择 | 用法 |
| --- | --- |
| 头像方图 | 请求方形构图 |
| 竖版人像 | 请求 3:4 构图 |
| 横版插画 | 请求 4:3 构图 |
| 手机壁纸 | 请求接近 9:16 的构图 |
| 宽屏封面 | 请求接近 16:9 的构图 |
| 手动宽高 | 在同一个输入框填写像素宽高，如 `1080:1920` |
| 模型自适应 | 在支持的模型和协议下选择原生分辨率档位、画面比例 |

场景预设会按渠道及已识别模型调整请求尺寸。例如，Seedream 与百炼使用各自的预设尺寸，部分已识别的 OpenAI 模型使用其支持的尺寸组合。因此，构图标签不保证所有渠道发送完全相同的像素值。

### 手动宽高

选择「手动宽高」后填写 `宽:高`：

```text
1080:1920    宽 1080、高 1920 像素
1024:1024    方形图片
0:0          未指定手动尺寸，默认值
1080:0       仅指定宽，另一边回退为 1024
```

这里的冒号分隔的是**像素宽高**。例如 `16:9` 会被解释为宽 16、高 9 像素；画面比例应在「模型自适应」中选择，或使用命令参数 `--ratio 16:9`。

`0:0` 不会自动选择某个场景预设。需要预设时直接选择对应场景；手动尺寸未指定时按渠道默认逻辑构造请求，内部宽高回退值为 1024，但部分原生协议会省略尺寸字段。

### 模型自适应、2K 与 4K

「模型自适应」根据**已保存的模型和调用协议**提供选项。更换模型或协议后，保存并重新打开配置以刷新。

- 2K／4K 是模型接口的原生档位，原样发送，不固定换算成 `2560×1440` 或 `4096×2160`。
- 最终像素尺寸取决于模型、档位、比例及服务端实现。
- Seedream 不提供独立的原生比例选项，可在提示词中描述构图。
- 即梦的「智能自动」位于「模型画面比例」中，发送智能比例参数；选择固定比例、场景预设或手动像素尺寸时不启用智能比例。
- 「模型默认」表示不指定对应的档位或比例，与即梦的「智能自动」不同。
- 原生档位请求失败时，不会静默改为像素尺寸重试；Grok 原生档位图生图使用 JSON 请求格式。

### 单次命令优先

命令中显式填写的宽高、尺寸或比例优先于渠道保存的布局设置；`--resolution` 可指定本次使用的分辨率档位。参数是否被上游接受仍取决于模型与协议。

```text
/draw gpt 一只猫 --size 1024x1024
/draw seedream 山间庭院 --size 2K
/draw gemini 未来城市 --ratio 16:9
/draw jimeng 樱花街道 --ratio 16:9 --resolution 2k
```

插件发送的是尺寸请求，无法保证上游严格返回指定像素，也不会在生成后强制缩放图片。

## 指令

### `/draw`：生成图片

```text
/draw [渠道[@工作流]] [参数] <提示词>
```

别名：`/生图`、`/画图`。

| 参数 | 说明 |
| --- | --- |
| `--size 1024x1024` / `-s` | 像素尺寸，支持 `x`、`*`、`×` 分隔 |
| `--size 2K` | 支持该写法的渠道原生档位，例如 Seedream |
| `--width 800` / `-w` | 本次宽度 |
| `--height 600` / `-h` | 本次高度 |
| `--ratio 16:9` | 支持该字段的渠道画面比例 |
| `--resolution 2k` / `--res` | 支持该字段的渠道分辨率档位 |
| `--n 2` / `--count 2` | 本次生成数量，受 `max_count` 和上游限制 |
| `--seed 123` | 随机种子，是否支持取决于上游 |
| `--negative 模糊,低质量` / `--neg` | 负向提示词，参数值不要包含空格 |

**默认请求生成 1 张。** 没有默认数量配置项，需要多张时使用 `--n`。

| 渠道 | 支持的别名 |
| --- | --- |
| `gpt` | `openai`、`chatgpt`、`dalle`、`gpt-image` |
| `gemini` | `google`、`imagen`、`nano`、`nanobanana`、`banana` |
| `comfyui` | `comfy`、`工作流` |
| `seedream` | `doubao`、`豆包`、`ark`、`方舟`、`seededit` |
| `grok` | `xai`、`x-ai` |
| `jimeng` | `即梦`、`dreamina`、`jm` |
| `qwen` | `万相`、`通义`、`百炼`、`dashscope`、`wanx` |

渠道选择顺序：**指令显式指定 → 本群设置 → 全局默认渠道**。

```text
/draw 一只橘猫
/draw gpt 一只橘猫 --size 1024x1024
/draw comfyui@anime 赛博朋克少女
/draw seedream 山间庭院 --size 2K
```

### `/draw_models`：查看渠道配置状态

别名：`/生图模型`、`/生图渠道`。

显示各渠道是「已就绪」「未配置」还是「配置不完整」，指出缺少的字段，列出 ComfyUI 工作流和当前会话渠道。

这里的「已就绪」表示必要配置已填写，**不代表已经通过真实生图验证**。该指令不受插件名单限制，方便查询配置状态；模型目录在管理面板中选择。

### `/draw_switch`：切换本群默认渠道

别名：`/生图切换`、`/切换生图`、`/切换渠道`。

```text
/draw_switch                     查看本群当前设置
/draw_switch seedream            切换本群默认渠道
/draw_switch comfyui@anime       同时指定工作流
/draw_switch 默认                 清除本群设置，跟随全局默认渠道
```

各群独立保存，重启或重载后仍有效。仅能切换到配置已就绪的渠道；此指令受准入名单限制，私聊请直接在 `/draw` 中指定渠道。

## 图生图与参考图

将参考图和提示词一起发送：

```text
[发送一张图片] /draw seedream 把背景换成雪山，保留主体
```

- 「最大参考图数量」`max_references` 默认为 3，**设为 0 即禁用参考图收集**，按文生图处理。
- 「参考图大小上限」`reference_max_mb` 默认为单张 8 MB。
- 无需额外启用图生图开关。
- 图像编辑模型可能必须带参考图；插件会对识别出的编辑模型提前提示。禁用参考图时应选择可文生图的模型。

| 渠道 | 参考图处理 |
| --- | --- |
| GPT / OpenAI 兼容 | `/images/edits`，multipart 上传 |
| Gemini 原生 | `inlineData` |
| Seedream | 生图接口中的 `image` 字段 |
| Grok | JSON 或 multipart；JSON 路径使用第一张参考图 |
| 即梦转换服务 | 图像合成接口，优先传原始 URL，否则按配置传 data URI／Base64 |
| ComfyUI | 上传图片后注入工作流参考图节点 |
| 百炼 | 根据模型使用对应的多模态或任务接口 |

开启 `use_file_service` 可尝试将本地参考图注册到 AstrBot 回调文件服务。需要正确配置框架的回调地址，并确保上游能访问得到。

## 各渠道配置要点

### 常用字段

以下字段按渠道提供，具体以配置页为准；ComfyUI 使用工作流，不需要模型名，也没有 `extra_body` 配置。

| 字段 | 作用 |
| --- | --- |
| `api_base` | API 或服务地址，支持常见版本前缀、完整接口地址的归一化 |
| `api_key` | API Key；即梦转换服务通常填 sessionid |
| `model` | 模型名称，支持目录选择的渠道可自动展示下拉框 |
| `manual_model_input` | 支持动态目录的渠道切换到手动输入模型 |
| `api_style` | 调用协议，提供此选项的渠道可自动尝试或手动指定 |
| `parameter_preset` | 常用参数预设，按渠道独立保存 |
| `dimensions` | 手动像素宽高，默认 `0:0`，仅手动宽高模式使用 |
| `native_resolution` / `native_ratio` | 模型自适应模式中的原生档位、比例 |
| `timeout` | 此渠道单次请求超时；多数渠道默认 180 秒，ComfyUI 默认 60 秒 |
| `force_download` | 此渠道由插件下载图片后发送 |
| `extra_headers` | 自定义请求头 |
| `extra_body` | 扩展请求参数，例如 `{"quality":"high"}` |
| `proxy` / `verify_ssl` | 代理与 TLS 证书校验配置 |

扩展请求参数只用于补充接口字段，**不能覆盖或重新注入**模型、提示词、尺寸、比例、数量、参考图等受正式配置管理的字段；嵌套请求体也遵循相同规则。

请求超时和强制代为下载均按渠道设置，没有同名全局开关。异步任务的总等待时间由相应渠道的 `max_wait` 另行控制。

### GPT / OpenAI 兼容

`gpt` 是通用协议槽位。只要服务提供兼容的图片生成接口，就可填写其地址、Key 与模型名；不要求模型来自 OpenAI。

- 官方地址示例：`https://api.openai.com`。
- `api_style=auto` 优先图片接口，在符合回退条件时尝试对话接口。
- 图生图需要服务端支持对应的编辑接口，文生图成功不代表图生图也可用。

### Gemini

- 原生地址示例：`https://generativelanguage.googleapis.com`。
- `api_style=auto` 尝试原生、Google OpenAI 兼容层及中转站 OpenAI 布局；`imagen` 类模型使用对应的预测路径。
- 对明确采用 OpenAI 图片接口的中转站，可选择 `api_style=openai`。
- `response_modalities` 默认 `TEXT,IMAGE`。
- 原生尺寸在「模型自适应」中选择；该模式不会切到无法保留原生档位的兼容协议。

一个渠道保存一组地址和凭证。需要在同一中转站使用两组模型时，可以让 `gpt` 与设为 OpenAI 协议的 `gemini` 分别配置模型，前提是服务端支持相应请求。

### ComfyUI

需要已部署且 AstrBot 可访问的 ComfyUI。填写根地址，例如 `http://127.0.0.1:8188`，并添加至少一套工作流模板；容器内的 `127.0.0.1` 指向容器自身。

- `workflows`：工作流模板列表，使用 ComfyUI **API 格式**导出的 JSON。
- `default_workflow`：默认工作流别名，留空使用第一个模板。
- `poll_interval`：默认 1 秒；`max_wait`：默认 300 秒。
- 通过 `/draw comfyui@别名 提示词` 切换模板。

支持占位符：`{{prompt}}`、`{{negative_prompt}}`、`{{width}}`、`{{height}}`、`{{seed}}`、`{{count}}`。也支持按节点类型注入或指定节点 ID。

### Seedream / 火山方舟

- 地址示例：`https://ark.cn-beijing.volces.com/api/v3`。
- 使用模型服务 API Key，以及账户已开通的模型 ID。
- 尺寸通过场景预设、手动像素宽高或模型自适应档位选择。
- `watermark` 默认关闭；`optimize_prompt` 默认关闭。
- 各模型支持的档位和最小像素要求可能不同，手动尺寸应符合所选模型要求。

### Grok / xAI

- 地址示例：`https://api.x.ai`。
- `model` 指定文生图模型；`edit_model` 可单独指定图生图模型，留空沿用 `model`。
- `size_mode` 控制普通尺寸请求采用 `size` 还是比例／档位写法。
- `edit_mode` 支持 `auto`、`json`、`multipart`；模型自适应档位的图生图需要 JSON。

### 即梦转换服务

此渠道接入使用 sessionid 的第三方转换服务，**未实现火山引擎 AK/SK 签名的即梦官方接口**。

- `api_base` 填转换服务地址，默认留空。
- `api_key` 填 sessionid，支持逗号或换行分隔多个凭证，并在可轮换的失败条件下尝试其他凭证。
- `sample_strength` 控制图生图采样强度，默认 0.7；具体语义由服务端决定。
- `reference_mode` 选择 data URI 或 Base64 写法。
- 智能比例在「常用参数预设 → 模型自适应 → 模型画面比例 → 智能自动」中选择。

### 阿里云百炼 / 通义万相

- 地址示例：`https://dashscope.aliyuncs.com`。
- 按模型使用原生同步多模态生成或异步任务接口，`api_style` 可选择 `auto`、`multimodal`、`text2image`。
- `poll_interval` 默认 2 秒，`max_wait` 默认 180 秒。
- `watermark`、`prompt_extend` 默认关闭。
- 没有显式尺寸时可省略尺寸字段；场景预设和手动尺寸会形成对应的请求尺寸。

## 全局配置

| 配置项 | 默认值 | 说明 |
| --- | --- | --- |
| `default_provider` | `gpt` | 默认生图渠道，可被本群设置和单次指令覆盖 |
| `test_connection_on_save` | 关闭 | 保存／加载后执行只读连通性检测 |
| `connection_test_time` | 尚未测试 | 自动记录的最近测试时间 |
| `connection_test_result` | 尚未测试 | 自动记录的检测结果，无需手动填写 |
| `max_count` | 4 | 单次请求的最大生成数量，默认请求仍为 1 张 |
| `max_references` | 3 | 最多使用的参考图数量，0 表示禁用参考图 |
| `reference_max_mb` | 8 | 单张参考图大小上限，单位 MB |
| `use_file_service` | 关闭 | 尝试将本地参考图注册到回调文件服务 |
| `admin_only` | 关闭 | 仅管理员可使用生图与切换渠道 |
| `admin_bypass` | 关闭 | 管理员绕过名单和频率限制 |
| `rate_limit_enabled` | 关闭 | 是否启用频率限制 |
| `rate_limit_scope` | `user` | 按人计数，或设为 `group` 按群共享额度 |
| `rate_limit_window_minutes` | 10 | 频率统计窗口，单位分钟 |
| `rate_limit_max_calls` | 5 | 窗口内最多受理的生成请求次数 |
| `group_whitelist` / `group_blacklist` | 空列表 | 群白名单／黑名单 |
| `group_user_whitelist` / `group_user_blacklist` | 空对象 | 按群配置的个人白名单／黑名单 |
| `one_task_per_session` | 开启 | 同一会话同时只运行一个生成任务 |
| `cache_keep_minutes` | 30 | 生成时清理过期历史缓存的保留时长；0 表示不自动按过期时间清理 |

### 准入与频率限制

名单按以下顺序判定：

1. 开启 `admin_only` 时拒绝非管理员。
2. 开启 `admin_bypass` 时管理员绕过后续名单及频率限制。
3. 群黑名单非空时，按群黑名单判定。
4. 否则群白名单非空时，按群白名单判定。
5. 群名单都为空时，使用当前群的个人名单；同一群的个人黑名单优先。
6. 没有配置名单时不限制。

群白名单启用时，私聊不放行；仅启用群黑名单时，私聊不受该群名单限制。群名单一旦启用，群内个人名单就不参与判定。

个人名单示例，键为群号，值为成员号数组：

```json
{
  "123456789": ["10001", "10002"]
}
```

频率限制与名单独立。请求取得会话任务位并被受理后计入次数，上游随后失败也可能占用这次额度；名单拒绝、限流拒绝和已有任务导致的拒绝不会计数。`group` 模式下，私聊仍按人计数。限流记录保存在内存，插件重载后清空。

## 数据保存与图片下载

插件数据位于 AstrBot 数据根目录下的：

```text
data/plugin_data/astrbot_plugin_multi_image/
├── group_channels.json    各群默认渠道
└── cache/                 下载或解码后的图片缓存
```

通过框架工具定位目录，支持 `ASTRBOT_ROOT` 等运行环境设置。标准插件数据目录接口不可用时，仍兜底到框架数据根目录的 `plugin_data` 下，**不会将持久化设置改存到系统临时目录**。

目录不可写时，群渠道保存失败会回滚内存设置并提示失败；图片缓存不可用时会返回错误。修复目录权限后可以重试。数据不写入插件代码目录，正常覆盖更新插件代码会保留这些数据。

每个渠道独立设置 `force_download`。代下载图片时，渠道鉴权只用于与 API 同源的地址；第三方图床及跨源重定向会隔离凭证。下载按流读取并执行默认 20 MB 大小上限。

缓存用于消息发送，不作为永久图片相册；插件停用或重载时会尝试删除本实例跟踪的临时图片，即使 `cache_keep_minutes=0` 也会执行此生命周期清理。

升级前可备份 AstrBot 中该插件的配置和数据目录。升级后保存并重新打开标准配置，检查默认渠道、模型和尺寸选择。

## 常见问题

**填完 Key 为什么没有立刻出现模型下拉？**

目录使用已保存的配置后台读取。先保存，等待读取完成，再重新打开配置页。若仍是输入框，检查地址、凭证和协议；服务不提供目录或模型命名未被识别时，可手动填写。

**连通性通过，为什么生成仍失败？**

只读接口可访问不代表模型已开通、有余额或支持图生图。结合实际生成错误检查模型 ID、调用权限、额度、尺寸限制和请求协议。

**4K 为什么不是固定的 4096×2160？**

此处 4K 是上游模型档位，具体像素和比例由模型决定。需要明确像素时改用手动宽高，但仍须符合上游支持范围。

**为什么生成图片与填写的尺寸不同？**

服务端可能调整或忽略尺寸，部分模型只支持有限组合。插件不在生成后强行缩放，实际输出以返回图片为准。

**只配了 Seedream，直接 `/draw` 却失败？**

全局默认渠道初始为 `gpt`。将默认渠道改为 `seedream`，或使用 `/draw seedream 提示词`，群内也可使用 `/draw_switch seedream`。

**参考图没有生效？**

检查 `max_references` 是否为 0、图片是否超限、消息平台是否提供可读取的图片，以及上游是否支持所选模型的编辑接口。

**图片生成成功但发送失败？**

检查平台的图片大小限制和图片链接可达性。可尝试开启对应渠道的强制代为下载，或选择较小尺寸；本地文件发送仍取决于消息平台适配器。

**为什么扩展请求参数中的 `model`、`size` 不生效？**

这些字段由模型选择、尺寸设置或命令参数管理，不允许在扩展请求参数中重复注入。
