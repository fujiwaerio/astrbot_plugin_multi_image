# AstrBot 多模型生图插件

在 AstrBot 聊天中用 `/draw` 调用七类生图渠道，支持文生图、随消息附带参考图、按群切换渠道，以及 ComfyUI 多工作流。

**当前版本：v0.2.1 · 最低要求：AstrBot ≥ 4.28.0。** 全部设置使用 AstrBot 标准插件配置页。配置好一个渠道即可使用，其余渠道可以留空。

## 快速开始

1. 在 AstrBot 插件管理中安装插件。手动安装时，将插件目录放到 AstrBot 的 `data/plugins/astrbot_plugin_multi_image/`，再重载插件或重启 AstrBot。运行依赖为 `httpx>=0.24`。
2. 打开 **插件 → 多模型生图 → 配置**，选择一个渠道，填写 API 地址、凭据和模型；ComfyUI 改为配置工作流。
3. 将 **默认生图渠道** 设置为已配置的渠道并保存。默认值为 `gpt`，只配置其他渠道时需要修改，或在命令中明确指定渠道。
4. 发送 `/draw_models` 查看配置状态，然后生成图片：

```text
/draw 一只坐在窗边的橘猫，柔和自然光
/draw gpt 水彩风格的山间小屋
```

默认每次请求 **1 张**；需要多张时在单次命令中加 `--n 2`。插件不提供默认数量配置。

## 支持的渠道

渠道用于选择接口协议。模型名称应填写当前服务实际提供的模型 ID；示例名称不代表账号已获得使用权限。

| 渠道 | 用途与接口 | 必要配置 |
| --- | --- | --- |
| `gpt` | 通用 OpenAI 兼容生图，支持图片接口及对话式生图 | API 地址、API Key、模型名称 |
| `gemini` | Gemini 原生、Imagen，以及 Gemini / 通用 OpenAI 兼容布局 | API 地址、API Key、模型名称、匹配的调用协议 |
| `comfyui` | 自建 ComfyUI，提交工作流、轮询并取图 | ComfyUI 地址、至少一套 API 格式工作流；Key 可选 |
| `seedream` | 火山方舟 Seedream / SeedEdit，使用 `/api/v3/images/generations` | 方舟地址、API Key、模型 ID |
| `grok` | Grok 图片生成与编辑，也支持兼容中转服务 | API 地址、API Key、文生图模型；可另设图生图模型 |
| `jimeng` | 即梦 2API 类服务，支持图片、compositions 和对话接口 | 服务地址、Session ID、模型名称 |
| `qwen` | 阿里云百炼原生生图，同步多模态或异步任务 | 百炼地址、API Key、模型名称 |

每个渠道独立保存一套地址、凭据和参数。没有部署 ComfyUI 时无需配置它；未配置的渠道不影响其他渠道使用。

## 聊天指令

### 生成图片：`/draw`

```text
/draw [渠道[@工作流]] [参数] <提示词>
```

别名：`/生图`、`/画图`。显式渠道应紧跟在指令后，例如 `/draw seedream 古风庭院`。

| 参数 | 别名 | 说明 |
| --- | --- | --- |
| `--size 1024x1024` | `-s` | 像素尺寸；也接受 `1024*1024`、`1024×1024`。插件按渠道转换，模型仍可能限制尺寸 |
| `--width 1024` | `-w` | 像素宽度，通常与高度一起指定 |
| `--height 1536` | `-h` | 像素高度，通常与宽度一起指定 |
| `--ratio 16:9` | — | 独立比例，适用于支持该参数的 Gemini 原生、Grok 图片、即梦协议 |
| `--resolution 2K` | `--res` | 原生分辨率档位，适用于已支持的 Gemini、Grok、即梦模型与协议 |
| `--size 2K` | `-s` | Seedream 原生档位，支持范围依模型而定 |
| `--n 2` | `--count` | 请求数量，受“单次最多生成数量”限制；超过上限时按上限处理 |
| `--seed 123` | — | 随机种子，是否生效取决于上游 |
| `--negative 模糊,低质量` | `--neg` | 负向提示词，是否生效取决于上游 |

参数必须带前缀，支持 `--size 1024x1024` 和 `--size=1024x1024`。`size=1024x1024` 会被当成提示词。参数值按空白分词，负向提示词请用逗号连接，避免在值中加入空格。同一条命令中尽量只用一种尺寸写法。

```text
/draw gpt 一只橘猫 --size 1024x1024
/draw gpt 雨中的街道 --n 2
/draw gemini 未来城市夜景
/draw comfyui@anime 水彩风格的山间小屋 --width 768 --height 768
/draw seedream 古风庭院 --size 2K
/draw grok 太空中的机械鲸鱼
/draw jimeng 春日樱花街道 --ratio 16:9
/draw qwen 简洁的咖啡店招牌设计
```

命令中的种子、数量、负向提示词和尺寸只是请求参数，具体支持程度及实际返回数量、尺寸由服务或工作流决定。

常用渠道别名：

| 标准名称 | 常用别名 |
| --- | --- |
| `gpt` | `openai`、`chatgpt`、`dalle`、`gpt-image` |
| `gemini` | `google`、`imagen`、`nano`、`nanobanana`、`banana` |
| `comfyui` | `comfy`、`工作流` |
| `seedream` | `doubao`、`豆包`、`ark`、`方舟`、`seededit` |
| `grok` | `xai`、`x-ai` |
| `jimeng` | `即梦`、`dreamina`、`jm` |
| `qwen` | `万相`、`通义`、`百炼`、`dashscope`、`wanx` |

`/draw nanobanana ...` 中的 `nanobanana` 是 Gemini **渠道别名**，不会把配置中的模型自动切换成同名模型。更换模型需要在配置页操作。

### 查看配置状态：`/draw_models`

别名：`/生图模型`、`/生图渠道`。

显示插件版本、当前群或私聊使用的渠道、各渠道配置状态和 ComfyUI 工作流别名。状态分为“已就绪”“未配置”“配置不完整”，缺少字段时会给出提示。

**“已就绪”表示必要配置齐全，不代表已完成真实生图验证。** 该指令不会生成图片，也不主动测试上游连接；它不受插件名单限制，便于查看配置状态。

### 切换本群渠道：`/draw_switch`

别名：`/生图切换`、`/切换生图`、`/切换渠道`。

```text
/draw_switch
/draw_switch seedream
/draw_switch comfyui@anime
/draw_switch 默认
```

不带参数时查看本群设置；指定渠道时保存本群默认渠道；“默认”清除本群覆盖，恢复跟随全局默认。设置按群独立保存，重启或重载后保留，只能切换到配置已就绪的渠道和有效工作流。

渠道选择顺序为：**单次 `/draw` 明确指定 → 本群设置 → 插件默认渠道**。

切换指令只在群聊中可用，与生图共用准入规则。通过准入检查的成员可切换本群渠道；如需限制使用者，请配置“仅管理员可用”或名单。

## 标准配置页

### 渠道通用设置

| 配置 | 作用 |
| --- | --- |
| API 地址、API Key / Session ID、模型名称 | 当前渠道的服务与身份；ComfyUI 使用工作流选择模型 |
| 常用参数预设 | 统一选择场景预设、手动宽高或受支持的模型自适应模式 |
| 请求超时 | 当前渠道单次 HTTP 请求的超时；ComfyUI 与百炼异步任务另有最长等待时间 |
| 强制代为下载图片 | 当前渠道返回 URL 时，由插件下载到本地后发送，适合需要鉴权的图片地址 |
| 附加请求头 | 服务要求的自定义请求头 |
| 扩展请求参数 | 补充没有专门设置的字段，例如 `quality`、`response_format`；ComfyUI 不提供此项 |
| HTTP(S) 代理、校验 TLS 证书 | 当前渠道的网络设置 |

超时、强制下载和尺寸分别在各渠道配置。扩展请求参数不能覆盖模型、提示词、参考图、数量、种子、尺寸、原生档位等受插件管理的字段；`parameters`、`generationConfig`、`imageConfig` 内的扩展字段也受同样限制。百炼的扩展参数会放入 `parameters`。

### 模型目录与手动输入

GPT、Gemini、Seedream、Grok、即梦支持读取当前地址和 Key 对应的生图模型目录：

1. 填写地址与凭据，保存配置。
2. 等待目录读取完成，重新打开配置页。
3. 在模型下拉框选择模型，再保存生效。

候选按上游能力信息和模型名称筛选，不会自动替换当前模型。当前模型未出现在目录中时仍保留，并标注“当前配置，目录未返回”。目录中可见不保证余额、生图权限或当前协议可用。

需要使用自定义 ID 时，开启 **手动填写模型名称** 并保存，重新打开配置即可输入。目录读取失败或没有候选时也会保留输入方式。候选只保存在当前实例内存中，不写入插件的 schema 文件。

目录读取使用 GET 请求，不调用生图接口。即使关闭“保存后测试连通性”，支持目录的渠道仍会刷新候选。ComfyUI 通过工作流选模型；百炼沿用配置页提供的模型选项。

### 保存后测试连通性

**保存后测试连通性**（`test_connection_on_save`）默认关闭。开启并保存后，插件会在初始化时测试连接：包括配置保存触发的重载、手动重载和 AstrBot 启动。

完成后重新打开配置，查看 **最近测试时间** 与 **最近一次测试结果**。结果显示各渠道状态、耗时、HTTP 状态码及原因；关闭开关后保留上次结果。

连接检测只发送 GET 只读请求，单渠道总耗时最多 15 秒，最多并发 3 个渠道；不生成图片、不提交 ComfyUI 工作流。缺少地址或凭据的渠道会跳过。结果字段自动记录，不需要手填，也不会因记录结果再次触发测试。

连通性通过只说明只读探测得到预期响应，不能确认生图权限、额度或完整工作流。接口不提供只读探测时可能显示“待确认”。检测延迟也不是生图耗时。

## 尺寸与生成前检查

### 场景预设与手动宽高

每个渠道的 **常用参数预设** 提供头像方图（1:1）、竖版人像（3:4）、横版插画（4:3）、手机壁纸（9:16）、宽屏封面（16:9）及手动宽高。

预设会按渠道和已识别模型转换为可用的像素或比例参数。因此，同名预设在不同渠道不一定发送相同像素，固定尺寸模型也不一定保留预设名称中的精确比例。

选择 **手动宽高** 后，在 **手动宽高（宽:高）** 中填写像素，例如 `1080:1920`。这里的冒号分隔两个像素值，`16:9` 在此处表示宽 16、高 9，不是画面比例。

- `0:0` 表示不从该字段指定尺寸；后续仍可能使用适配器默认值，例如 GPT 图片协议的 1024×1024 或 Seedream 的 2K。
- 只指定一边时可写 `1080:0`，缺少的一边回退为 1024。也接受中文冒号和冒号两侧空格。
- 单次命令明确指定宽高、尺寸或比例时优先使用命令值。切回场景预设后不使用手动值，但会保留该值。
- 插件只请求尺寸，不在生成后强制缩放图片。

### 模型自适应：原生档位与比例

对已识别且支持原生设置的模型和协议，预设下拉框还会提供 **模型自适应**，按需显示 **模型分辨率档位**、**模型画面比例**。2K、4K 等档位直接交给模型，不换算为固定像素。

| 渠道 | 尺寸处理特点 |
| --- | --- |
| GPT | 图片协议使用像素 `size`；对话生图协议可能不发送明确像素字段 |
| Gemini | 原生协议按需发送比例和受支持的档位；Imagen 使用比例；OpenAI 兼容协议使用图片尺寸 |
| ComfyUI | 注入工作流尺寸节点或占位符，实际出图由工作流决定 |
| Seedream | 使用像素或原生档位；模型自适应不提供独立比例框，构图比例可在提示词中描述 |
| Grok | 支持像素或比例与档位；原生档位图生图需要 JSON 请求格式 |
| 即梦 | 转换为比例与分辨率；“智能自动”由服务端根据提示词或参考图决定比例 |
| 百炼 | 使用模型支持的像素尺寸，以 `*` 分隔；未显式指定时可不发送尺寸字段 |

可选档位按已保存的模型与协议生成。修改模型或协议后，先保存，再重新打开配置刷新。历史未知档位会保留并标注待确认，不代表当前模型支持。

即梦的 **智能自动** 与 **模型默认** 含义不同：前者请求服务自动判断比例，后者不指定比例。选择固定比例、场景预设、手动宽高或命令尺寸时，会关闭智能比例。

原生档位不会在兼容回退时被静默改成像素；Gemini 模型自适应模式不跨协议回退。需要兼容协议时，应改用该协议支持的尺寸设置。

### 生成前检查的范围

提交前会检查必要配置、编辑模型的参考图要求、已识别模型的尺寸与数量，以及命令覆盖后的原生档位、比例和请求格式。被这些检查拦截的请求不会提交生成任务，也不记入新的插件限流次数。

固定像素检查目前覆盖以下模型在适用的图片协议下的请求；带目录前缀的同名模型也可识别：

| 模型 | 支持的像素尺寸 | 其他检查 |
| --- | --- | --- |
| `dall-e-2` | 256×256、512×512、1024×1024 | — |
| `dall-e-3` | 1024×1024、1792×1024、1024×1792 | 单次只允许 1 张 |
| `gpt-image-1` | 1024×1024、1536×1024、1024×1536 | 支持 `auto` 尺寸 |

这不是所有上游模型的能力表。**v0.2.1 没有将 `gpt-image-2` 纳入上述固定像素名单**；未知或自定义模型保留尺寸灵活性，是否支持参数由上游决定。原生档位按各渠道的独立规则检查，目录可见也不会自动增加本地校验规则。

## 图生图与渠道专用设置

### 参考图

把参考图和 `/draw` 提示词放在**同一条消息**中发送。插件读取当前消息中的图片，不保证收集历史消息或引用消息里的图片。

| 配置 | 默认值 | 作用 |
| --- | --- | --- |
| 参考图数量上限（`max_references`） | 3 | 设为 **0** 时不读取参考图，关闭参考图收集 |
| 单张参考图大小上限（`reference_max_mb`） | 8 MB | 超过上限的图片会跳过 |
| 把本地参考图注册到 AstrBot 回调文件服务（`use_file_service`） | 关闭 | 为只接受图片 URL 的服务提供地址，需要 AstrBot 配置可访问的 `callback_api_base` |

超过数量上限的参考图会忽略，无法读取、为空或超过大小上限的图片会跳过。实际使用一张还是多张参考图取决于渠道和模型。

已识别的 `image-edit`、`seededit`、`inpaint`、`outpaint` 等编辑模型需要参考图；缺少参考图时会在提交前提示。Grok 配置了“图生图模型”时，带参考图的请求使用该模型进行校验和生成。

### ComfyUI 多工作流

1. 从 ComfyUI 导出 **API 格式** JSON，普通画布工作流 JSON 不能直接使用。
2. 在插件配置的“工作流模板”中添加条目，填写别名，例如 `anime`。
3. 粘贴“工作流 JSON”，或填写 AstrBot 所在机器可读取的“工作流文件路径”。两者都填时优先使用内联 JSON。
4. 按需填写“默认工作流别名”。未指定默认别名时使用第一套模板。

```text
/draw comfyui@anime 山间小屋，水彩风格
/draw_switch comfyui@anime
```

模板支持 `{{prompt}}`、`{{negative_prompt}}`、`{{width}}`、`{{height}}`、`{{seed}}`、`{{count}}`、`{{batch_size}}` 占位符。没有占位符时，插件会尝试按常见节点类型注入提示词、尺寸、种子和参考图；复杂工作流可显式设置正向、负向、尺寸、采样器及图片输入节点 ID。

工作流依赖的模型和自定义节点需要在 ComfyUI 服务中准备好。复杂任务可调整该渠道的“最长等待时间”；它与单次 HTTP 请求超时分别生效。

### 其他渠道的专用选项

| 渠道 | 主要专用设置 |
| --- | --- |
| Gemini | 调用协议、返回模态；原生模型和兼容中转服务应选择匹配的协议 |
| Seedream | 水印、官方提示词优化；文生图和图生图使用同一生成接口 |
| Grok | 独立图生图模型、尺寸参数写法、图生图 JSON / multipart 格式 |
| 即梦 | 图生图采样强度、参考图 data URI / Base64 写法、调用协议 |
| 百炼 | 水印、提示词智能改写、同步 / 异步协议、异步轮询间隔与最长等待时间 |

百炼 `auto` 按模型名称选择同步多模态或异步任务路径，图片生成不直接使用普通对话的 OpenAI 兼容接口。

即梦的 Session ID 字段可用逗号或换行填写多个凭据；明确的 401、403、429 错误可尝试下一个。结果不确定时停止轮换，避免再次提交。

## v0.2.1 请求保护与生成反馈

### 减少结果不确定时的重复提交

当生成提交发生读取或写入超时、连接中断，或无法确认是否受理的服务端错误时，插件停止自动重提，也不继续切换协议、Grok 请求格式或即梦凭据。

**此时上游可能已经生成或计费。请先检查上游任务和账单，再决定是否手动重试。** 该保护减少插件重复提交的风险，不能承诺上游绝不重复生成或扣费。

连接前失败、连接池等待失败、明确限流，以及只读查询和图片下载仍保留有限重试。服务明确拒绝接口或参数时，也可能进行相应的兼容性尝试；因此，一次命令不一定只有一个 HTTP 请求。

收到成功响应却没有有效图片时，插件直接返回失败提示，不会为寻找图片而换协议再次生成。错误反馈会尽量提取简短原因，避免把整页 HTML 错误发到聊天中。

### 可选生成反馈

**生成进度与结果提示**（`generation_feedback`）默认关闭。开启后，生成前提示“正在生成”，完成后显示返回数量、总耗时、实际尺寸，以及明确像素请求与返回尺寸的差异。

```text
正在生成图片，请稍候……
[图片]
生成完成：1 张，总耗时 12.3 秒。
第 1 张：实际 1024×1024；请求 1536×1024，上游返回尺寸与请求不一致。
```

这是开始与完成提示，不提供实时百分比。总耗时包括本次处理和图片准备时间。

实际尺寸通过有界图片文件头读取，支持 PNG、JPEG、WebP、GIF、BMP。开启反馈后，URL 图片会先通过现有下载保护下载到缓存用于核验并发送，不额外调用生图接口。其他格式或无法核验的文件会提示“尺寸未能核验”。

- 未启用该渠道的“强制代为下载图片”时，核验下载失败仍保留原 URL 供消息平台发送。
- 已启用强制下载时，下载失败会返回错误。
- 只比较最终成功请求中**实际发送的像素字段**。原生档位、比例、未发送像素字段的对话请求，以及兼容重试中已移除尺寸字段的请求，不会根据内部默认宽高误报像素差异。

## 权限、频率与并发

### 准入规则

`/draw` 和 `/draw_switch` 使用同一套规则，按以下顺序判断：

1. 开启“仅管理员可用”时，拒绝非管理员。
2. 开启“管理员绕过限制”时，管理员跳过群和个人名单检查，并免于频率限制。
3. 群黑名单非空时，只按群黑名单判断；否则，群白名单非空时，只允许白名单群。
4. 群黑白名单都为空时，按当前群的个人名单判断；该群个人黑名单非空时优先使用黑名单，否则使用个人白名单。

**启用任一群名单后，群内个人名单整体不参与判断。** 群黑白名单应只填一项，同一群的个人黑白名单也应只填一项。管理员由 AstrBot 的管理员身份判断，不等同于所有平台的群管理员。

个人名单的键为群号，值为成员号数组，例如：

```json
{
  "123456": ["10001", "10002"]
}
```

`/draw_models` 仅查看配置状态，不受这些名单限制。

### 频率限制与并发保护

| 配置 | 默认值 | 说明 |
| --- | --- | --- |
| 启用频率限制（`rate_limit_enabled`） | 关闭 | 开启后按滑动窗口统计 |
| 限制维度（`rate_limit_scope`） | `user` | 按用户独立计数；`group` 为群内共用额度，私聊仍按用户 |
| 统计窗口（`rate_limit_window_minutes`） | 10 分钟 | 当前统计窗口长度 |
| 窗口内最多生成几次（`rate_limit_max_calls`） | 5 次 | 按请求次数统计，多张请求也是一次 |
| 单次最多生成数量（`max_count`） | 4 张 | 限制单条命令的请求数量 |
| 同一会话同时只允许一个生图任务（`one_task_per_session`） | 开启 | 任务进行中拒绝同会话的新请求 |

通过前置检查、准备执行生成时记入一次插件限流；之后上游失败也可能占用这次次数。被准入、本地参数检查、并发或限流检查拒绝的请求不新增计数。插件限流不是上游计费记录。

限流与并发记录保存在当前进程内，插件停用或重载时清理。管理员频率豁免不会关闭同会话并发保护。

## 数据保存与升级

渠道地址、凭据、模型、预设和插件开关由 AstrBot 的标准插件配置管理。群渠道选择和本地图片缓存使用框架数据根目录下的统一位置：

```text
data/plugin_data/astrbot_plugin_multi_image/
├── group_channels.json
└── cache/
```

常规路径及兜底路径都基于 AstrBot 数据根目录，不依赖启动工作目录。插件更新时需要保留配置和插件数据目录。

**本地图片缓存保留时长**（`cache_keep_minutes`）默认为 30 分钟，在处理生成请求时清理过期文件；0 表示不按时长自动清理。插件卸载或重载时仍会清理当前实例跟踪的临时图片。缓存不作为长期图库。

从旧配置升级时，尺寸与比例字段会一次性迁移到统一预设入口，已有新手动尺寸优先保留。当前配置不再提供全局宽高、默认数量、全局请求超时、全局强制下载和独立的图生图启用开关；参考图收集由 `max_references` 控制。隐藏的历史迁移字段不需要手动维护。

## 中转服务与常见问题

### 有 Key，为什么仍然不能生图？

确认该 Key 有目标图片模型的权限和额度，并且服务支持所选生成协议。模型目录和只读连通性通过都不能替代真实生成验证。查看 `/draw_models` 补齐配置，再核对地址、模型 ID 和调用协议。

### OpenAI 兼容中转服务应该填在哪个渠道？

通用 OpenAI 图片或对话式生图优先使用 `gpt`。服务采用 Gemini 原生布局时使用 `gemini`；只有 OpenAI 兼容布局时可选择匹配的兼容协议。插件可归一化常见地址前缀，也可在明确拒绝接口或参数时尝试兼容处理，但不能保证任意中转站都支持。

### 尺寸参数为什么与出图不同？

模型可能只支持固定尺寸、比例或原生档位，也可能由中转服务或工作流决定最终尺寸。插件不会强行缩放。开启“生成进度与结果提示”可核验实际尺寸；没有发送明确像素字段时，不进行像素差异比较。

### 图片链接能返回，但平台发不出来？

在对应渠道开启“强制代为下载图片”，并确认 AstrBot 服务器能够下载该图片。渠道凭据只用于与 API 同源的图片请求，跨源跳转不会转发渠道凭据或自定义私有请求头；需要独立图床鉴权的场景可能仍需调整服务配置。

### 生成超时后能否立即再发一次？

先查看错误是否提示“上游可能已受理”，并检查上游任务或账单。超时并不能证明生成失败。可以根据服务速度调整该渠道的请求超时；异步任务还需要检查最长等待时间。

### 带了参考图为什么仍提示需要参考图？

确认图片与命令在同一条消息中，参考图上限大于 0，且图片能够读取并未超过大小上限。只接受 URL 的服务还需要可访问的图片地址或 AstrBot 回调文件服务。
